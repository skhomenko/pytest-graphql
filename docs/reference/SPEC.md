## 0. Decision log

Every decision below was made during the design interview. This section is the short
form. The rest of the document is the detail.

| Topic | Decision |
|---|---|
| Product shape | Core library with zero pytest imports, plus a thin pytest plugin. One PyPI distribution. |
| Primary use | Functional and end-to-end tests against a running GraphQL server. |
| Runner support | pytest first. `unittest` and plain scripts supported through the core. |
| Selection sets | Auto-generated by default (pull everything, bounded). Explicit `fields=` narrows it. |
| Selection syntax | Pythonic first (lists, dicts, `Field`, `Selection`). Raw GraphQL string also accepted. |
| Schema source | Live introspection by default. `SchemaSource` protocol allows SDL and other sources. |
| Schema cache | In memory per session per worker. Optional disk cache, off by default. |
| Response model | Node objects with snake_case attributes and exact-key access. Raw response never lost. |
| Node strictness | Strict. Unknown field access raises with available fields and a suggestion. |
| Return value | The data node, with the full response attached at `__response__`. |
| GraphQL errors | Raise by default, including on partial data. Opt out per call. |
| Local validation | Full validation before sending. `validate=False` per call, `--gql-no-validate` globally. |
| Assertions | Plain `assert` plus a partial matcher (`gql.expect.User(...)`) and `gql.expect_error(...)`. |
| List matching | Positional by default. `contains`, `unordered`, `length`, `any_length` helpers. |
| Input factory | `gql.fake.<InputType>(...)`, seeded and reproducible from the test node id. |
| Input wrapping | Auto-wrap flat kwargs when a mutation has exactly one input-object argument. |
| HTTP layer | `httpx`, behind a `Transport` protocol. One pooled client per session. |
| Async | Sync only in v1. Internals kept I/O free so async is additive later. |
| Auth | Cloneable client (`with_headers`, `as_`) plus an `Auth` protocol. |
| Retries | Connect failures only. Never mutations, never read timeouts, never 5xx. |
| Diagnostics | pytest report section on failure with query, variables, response and a `curl` line. |
| Extensibility | Plain registries and protocols in the core. pytest hookspecs delegate to them. |
| Dependencies | Exactly two required: `graphql-core`, `httpx`. Everything else is an extra. |
| Compatibility | Python 3.10 to 3.14. pytest 7.4+. Any spec-compliant GraphQL server. |
| Versioning | 0.x first, strict semver from 1.0. |
| Licence | MIT. |
| v1 scope | Includes polling. Excludes uploads (1.1), async and subscriptions (2.0), record/replay (rejected). |

## 1. Goals

1. **Remove GraphQL boilerplate from tests.** A test should call an operation by name
   and get data back, without hand-writing a query string or a selection set.
2. **Fail fast and fail clearly.** Mistakes should be caught locally, before a network
   call, with a message that names the problem and the fix. When a test does fail, the
   report must show the exact query, variables and response.
3. **Test against the live schema.** The schema is fetched from the server under test on
   every run, so a developer's breaking change fails the suite immediately.
4. **Be usable outside pytest.** The core library must have no pytest import, so it works
   in `unittest`, CI scripts, load-test setup and a REPL.
5. **Be safe to install.** Two dependencies, no version pins that fight a user's project.
6. **Be extensible without forking.** Transports, auth, scalars, selection policy and
   request middleware are all replaceable through documented protocols.
7. **Be typed.** The public API is fully annotated and passes `mypy --strict`.

## 2. Non-goals

1. **Not a GraphQL client for production code.** No caching layer, no normalized store,
   no optimistic updates, no query batching for performance. Test ergonomics beat
   production concerns everywhere the two conflict.
2. **Not a schema linter or breaking-change detector.** Those are separate tools.
3. **Not a mock GraphQL server.** The package tests real servers. A mock `Transport` is
   provided for the package's own test suite and documented as an extension point, but
   building a mock server is out of scope.
4. **Not record and replay.** Explicitly rejected: recorded responses make tests pass
   against a contract that no longer exists, which defeats goal 3.
5. **Not code generation.** No generated typed models or `.pyi` stubs in v1. Reconsidered
   for 2.0 only if user demand is clear.
6. **Not tied to any server library.** No Strawberry, Graphene, Ariadne or Django
   integration code. Anything spec-compliant over HTTP works.
7. **Not a general HTTP testing tool.** REST endpoints are out of scope.

### 3.2 `GraphQLClient`

```python
class GraphQLClient:
    def __init__(
        self,
        *,
        transport: Transport,
        schema: GraphQLSchema,
        config: ClientConfig | None = None,
        scalars: ScalarRegistry | None = None,
        seed: int = 0,
        middleware: Sequence[Middleware] = (),
    ) -> None: ...

    # --- calling operations -------------------------------------------------

    def query(self, name: str, /, **variables: Any) -> Any: ...
    def mutation(self, name: str, /, **variables: Any) -> Any: ...
    def execute(
        self,
        document: str,
        variables: Mapping[str, Any] | None = None,
        *,
        operation_name: str | None = None,
        **options: Any,
    ) -> Any: ...

    # --- namespaces ---------------------------------------------------------

    @property
    def queries(self) -> OperationNamespace: ...
    @property
    def mutations(self) -> OperationNamespace: ...
    @property
    def fake(self) -> FakeNamespace: ...
    @property
    def expect(self) -> ExpectNamespace: ...
    @property

    # --- identity -----------------------------------------------------------

    def with_headers(self, **headers: str) -> GraphQLClient: ...
    def with_auth(self, auth: Auth) -> GraphQLClient: ...
    def as_(self, auth: Auth | str) -> GraphQLClient: ...   # str is treated as a Bearer token
    def anonymous(self) -> GraphQLClient: ...

    # --- assertions and polling ---------------------------------------------

    def expect_error(
        self,
        *,
        code: str | None = None,

    ) -> ContextManager[CapturedErrors]: ...

    def wait_until(

        *,
        until: Callable[[Any], bool],
        timeout: float = 30.0,
        interval: float = 1.0,
        backoff: float = 1.0,
        ignore: tuple[type[BaseException], ...] = (),
        **variables: Any,
    ) -> Any: ...
```

#### Per-call options

`query`, `mutation` and `execute` accept these keyword-only options. All are optional
and fall back to `ClientConfig`.

| Option | Type | Default | Meaning |
|---|---|---|---|
| `fields` | selection | `AUTO` | Explicit selection set. See 3.3. |
| `variables` | `dict` | `None` | Escape hatch for variables whose name collides with an option name. Merged with `**variables`; explicit dict wins. |
| `raw` | `bool` | `False` | Return the full `GraphQLResponse` instead of the data node. |
| `validate` | `bool` | `True` | Run local validation before sending. |
| `raise_on_error` | `bool` | `True` | Raise `GraphQLExecutionError` if the response has errors. |
| `raise_on_partial` | `bool` | `True` | Raise `GraphQLPartialDataError` when data and errors are both present. |
| `max_depth` | `int` | `3` | Auto-selection depth cap. |
| `cycle_policy` | `"stop" \| "shallow" \| "id_only"` | `"shallow"` | Behaviour when a type reappears on the current path. |
| `per_type_depth_cap` | `dict[str, int]` | `{}` | Stricter caps for named types. |
| `include_deprecated` | `bool` | `True` | Include `@deprecated` fields in auto-selection. |
| `max_fields` | `int` | `2000` | Guard against selection explosion. |
| `operation_name` | `str` | operation name | Name written into the document. |
| `timeout` | `float` | `30.0` | Seconds. |
| `retries` | `int` | `2` | Connect-failure retries. Ignored for mutations unless `idempotent=True`. |
| `idempotent` | `bool` | `False` | Mutations only. Opts this call into retrying. |
| `headers` | `dict[str, str]` | `{}` | Extra headers for this call only. |

**Name collision rule.** Option names are keyword-only and reserved. A GraphQL argument
that shares a name with an option (for example an argument literally called `fields` or
`timeout`) must be passed through `variables={...}`. Local validation detects the
collision and raises `ArgumentError` naming the fix.

### 3.3 Selection syntax

`fields=` accepts four interchangeable forms, all normalized to one graphql-core AST.

```python
# 1. sentinel: auto-generate (the default)
gql.query("user", id=1)
gql.query("user", id=1, fields=AUTO)

# 2. Pythonic list / dict
gql.query("user", id=1, fields=["id", "name", {"settings": ["id", "theme"]}])

# 3. Field objects, for arguments, aliases and directives
gql.query("user", id=1, fields=[
    "id", "name",
    Field("orders", args={"first": 10, "status": "PAID"}, alias="recent",
          fields=["id", "total"]),
])

# 4. raw GraphQL selection string
gql.query("user", id=1, fields="id name settings { id theme } orders(first: 10) { id }")
```

`Selection` is a reusable, named bundle of any of the above. Defining selections once is
the intended answer to schema churn.

```python
USER_BRIEF = Selection("id", "name", {"settings": ["id"]})
USER_FULL  = USER_BRIEF + Selection(Field("orders", args={"first": 50}, fields=["id", "total"]))

gql.query("user", id=1, fields=USER_BRIEF)
```

`Field` signature:

```python
Field(
    name: str,
    *,
    args: Mapping[str, Any] | None = None,
    alias: str | None = None,
    fields: SelectionInput | None = None,
    on: str | None = None,          # inline fragment: ... on ConcreteType
    directives: Mapping[str, Mapping[str, Any]] | None = None,
)
```

`Selection` supports `+` (union), `-` (remove field names) and `Selection.of(TypeName)`
for a schema-checked construction that validates field names at build time.

### 3.4 Response objects

`Node` is a mapping-like object over one JSON object in the response.

```python
class Node(Mapping[str, Any]):
    __response__: GraphQLResponse
    __typename__: str | None

    def __getattr__(self, name: str) -> Any: ...      # snake_case, strict
    def __getitem__(self, key: str) -> Any: ...       # exact schema key or snake_case
    def __contains__(self, key: str) -> bool: ...
    def at(self, path: str, default: Any = _RAISE) -> Any: ...
    def to_dict(self) -> dict[str, Any]: ...          # raw, original keys
    def keys(self) -> KeysView[str]: ...              # original keys
    def __eq__(self, other: object) -> bool: ...
    def __repr__(self) -> str: ...                    # type name plus field list
```

Rules:

- Attribute access uses snake_case. `user.first_name` reads `firstName`.
- Key access accepts the exact schema key or the snake_case form. `user["firstName"]`
  and `user["first_name"]` both work.
- Original keys are never lost. `to_dict()` and `keys()` return exactly what the server
  sent.
- Accessing a field not present in the response raises `GraphQLFieldError` listing the
  available fields with a closest-match suggestion (see 8.3).
- A field that was selected and came back `null` returns `None` normally. Absent and
  null are different.
- If two keys in one object collapse to the same snake_case attribute (`userId` and
  `user_id`), `Node` construction raises `GraphQLFieldError` naming both keys. Key
  access still works for both.
- Comparison against a `Matcher` returns `NotImplemented`, so Python falls back to the
  matcher's `__eq__`. Both `node == matcher` and `matcher == node` behave identically.

`NodeList` is a `list` subclass for list-valued results.

```python
class NodeList(list[Any]):
    def where(self, **eq: Any) -> NodeList: ...        # filter
    def first(self, **eq: Any) -> Any: ...             # first match, raises if none
    def one(self, **eq: Any) -> Any: ...               # exactly one match, else raises
    def find(self, **eq: Any) -> Any | None: ...       # first match or None
    def pluck(self, path: str) -> list[Any]: ...       # ["id"] from every element
    def at(self, path: str) -> Any: ...
    def ids(self) -> list[Any]: ...                    # shorthand for pluck("id")
```

`GraphQLResponse` is the envelope.

```python
@dataclass(frozen=True)
class GraphQLResponse:
    data: Node | NodeList | Any | None
    errors: tuple[GraphQLErrorInfo, ...]
    extensions: Mapping[str, Any]
    http: HttpInfo            # status, reason, headers, url, elapsed_ms
    request: RequestInfo      # operation, kind, document, variables, headers (redacted), curl()
    raw: Mapping[str, Any]    # untouched parsed JSON body
    duration_ms: float

    def unwrap(self) -> Any: ...          # the single top-level field value
    def assert_no_errors(self) -> None: ...
    def assert_data_contains(self, expected: Mapping[str, Any] | Matcher) -> None: ...
    def at(self, path: str, default: Any = _RAISE) -> Any: ...
```

```python
@dataclass(frozen=True)
class GraphQLErrorInfo:
    message: str
    path: tuple[str | int, ...] | None
    locations: tuple[tuple[int, int], ...] | None
    extensions: Mapping[str, Any]

    @property
    def code(self) -> str | None: ...   # extensions["code"], the de-facto standard
```

### 3.5 Return value contract

`query`, `mutation` and `execute` return **the value of the single top-level field**,
not the envelope.

| Server returns | Call returns |
|---|---|
| `{"data": {"user": {...}}}` | `Node` for the user object |
| `{"data": {"users": [...]}}` | `NodeList` of `Node` |
| `{"data": {"count": 7}}` | `7` |
| `{"data": {"user": null}}` | `None` |
| `raw=True` | `GraphQLResponse` |

The envelope is always reachable at `result.__response__` for `Node` and `NodeList`.
Scalar and `None` results cannot carry the attribute, so `raw=True` is the documented
route for those cases.

If a document produced by `execute` has more than one top-level field, the full
`GraphQLResponse` is returned regardless of `raw`.

### 3.6 Matchers

```python
expected = gql.expect.User(
    first_name="John",
    last_name="Doe",
    settings=gql.expect.Settings(theme="dark"),
    orders=contains([{"total": 150}]),
)
assert retrieved_user == expected
```

Semantics:

- **Objects: partial.** Only the fields present in the matcher are compared. Every other
  field in the response is ignored.
- **Field names are schema-validated.** `gql.expect.User(frist_name="John")` raises
  `SelectionError` at construction time, not at assertion time.
- **A matcher field missing from the response fails the assertion.** If you assert on it,
  it must be there. Use `absent("field")` to assert the opposite.
- **Lists: positional by default.** Same length, compared index by index, each element
  partial-matched.
- **Nesting is unlimited.** Matchers, plain dicts and plain lists can be mixed freely.
  A plain dict inside a matcher behaves as a nested partial match but is not
  schema-validated.

Helpers:

| Helper | Meaning |
|---|---|
| `contains([...])` | Every expected element appears somewhere. Extras allowed. |
| `unordered([...])` | Same multiset, any order. |
| `length(3)` / `any_length()` | Constrain list length only. |
| `any_value()` | Field must be present, value ignored. |
| `absent()` | Field must not be present in the response. |
| `matches(r"^u_\d+$")` | Regex against the string value. |
| `approx(1.5, rel=1e-3)` | Numeric tolerance. |
| `gt(0)`, `gte`, `lt`, `lte` | Numeric and date comparison. |
| `one_of("A", "B")` | Value is in a set. |

Matchers compose: `orders=contains([gql.expect.Order(total=gt(100))])`.

### 3.7 Input factory

```python
payload = gql.fake.CreateUserInput()                       # every field filled
payload = gql.fake.CreateUserInput(email="fixed@example.com")   # overrides win
payload = gql.fake.CreateUserInput(_required_only=True)    # skip nullable fields
payload = gql.fake.CreateUserInput(_depth=2)               # nested input object depth

gql.mutation("createUser", **payload)
gql.mutation("createUser", input=payload)
```

Rules:

- Values come from a seeded RNG. The seed is `hash(global_seed, test_node_id)`, so the
  same test produces the same data on every run. The effective seed is printed in the
  pytest header and in the failure report.
- Non-null fields are always filled. Nullable fields are filled by default and skipped
  with `_required_only=True`.
- Enums pick a value from the RNG, never the literal first value, so a test does not
  silently depend on enum declaration order.
- Nested input objects expand to `_depth` (default 2). Recursive input types are cut at
  the cap and filled with required fields only.
- List fields get one to three elements by default.
- Custom scalars resolve through the `ScalarRegistry`. An unregistered custom scalar
  raises `ScalarNotRegisteredError` with the exact registration snippet in the message.
- The return value is a plain `dict`, so it can be edited, merged and asserted on.

**Uniqueness.** Seeded values are reproducible, which means the same test writing to a
database with a unique constraint collides on the second run. Use `unique()` for those
fields:

```python
gql.fake.CreateUserInput(email=unique("email"), username=unique())
```

`unique()` mixes a session-scoped run id (printed in the header) into the value, so it is
unique across runs but still traceable back to a specific run. This tradeoff is
documented prominently: reproducible and unique are mutually exclusive, and the user
chooses per field.

### 3.8 Error assertions

```python
with gql.expect_error(code="FORBIDDEN"):
    gql.query("adminReport")

with gql.expect_error(path=["createUser", "email"], message_matches="already exists"):
    gql.mutation("createUser", email=existing_email)

with gql.expect_error() as captured:
    gql.mutation("createUser", email="bad")
assert len(captured.errors) == 2
assert captured.response.http.status == 200
```

- The block must raise `GraphQLExecutionError`, otherwise `ExpectedErrorNotRaised` is
  raised with the successful response in the message.
- Every supplied filter must match at least one error in the response. Unmatched filters
  produce a failure listing all errors that were actually returned.
- `captured` exposes `.errors`, `.response` and `.first`.

### 3.9 Polling

```python
order = gql.wait_until(
    "order",
    id=order_id,
    until=lambda o: o.status == "SHIPPED",
    timeout=60,
    interval=2,
    backoff=1.5,
)
```

- Re-runs the operation until `until` returns truthy or the timeout expires.
- On timeout raises `WaitTimeoutError` containing the number of attempts, the elapsed
  time, and the last response, which is included in the failure report section.
- `interval` is the first delay; `backoff` multiplies it each attempt, capped at
  `interval * 10`.
- Exceptions listed in `ignore` are swallowed and treated as "not ready yet". Everything
  else propagates immediately.
- Queries only. `wait_until` refuses a mutation name and raises `ArgumentError`.

### 3.11 Standalone construction (no pytest)

```python
from pytest_graphql import build_client

gql = build_client(
    url="https://api.example.com/graphql",
    headers={"Authorization": f"Bearer {token}"},
    max_depth=3,
)
user = gql.query("user", id=1)
```

`build_client` fetches the schema, builds a transport, and returns a `GraphQLClient`. It
is the documented entry point for `unittest`, scripts and notebooks.

```python
class GraphQLTestCase(unittest.TestCase):
    gql: ClassVar[GraphQLClient]

    @classmethod
    def setUpClass(cls):
        cls.gql = build_client(url=os.environ["GRAPHQL_URL"])

    def test_user(self):
        user = self.gql.query("user", id=1)
        self.assertEqual(user, self.gql.expect.User(name="John"))
```

## 4. Usage examples

### 4.1 Minimum setup

```ini
# pytest.ini
[pytest]
gql_url = http://localhost:8000/graphql
```

```python
def test_user_has_a_name(gql):
    user = gql.query("user", id="123")
    assert user.name
```

That is the whole setup. The schema is introspected once per session, the selection set
is generated automatically, and errors raise.

### 4.2 Authentication

```python
# conftest.py
import pytest
from pytest_graphql import BearerAuth

@pytest.fixture(scope="session")
def admin_token(): ...

@pytest.fixture
def gql_auth(admin_token):
    return BearerAuth(admin_token)
```

```python
def test_visibility(gql, customer_token):
    assert gql.query("me").role == "ADMIN"
    assert gql.as_(customer_token).query("me").role == "CUSTOMER"
    with gql.anonymous().expect_error(code="UNAUTHENTICATED"):
        gql.anonymous().query("me")
```

Cloned clients share the schema and the connection pool, so switching identity costs
nothing.

### 4.8 Raw GraphQL escape hatch

def test_aliases_and_fragments(gql):

## 5. Architecture

### 5.1 Layers

```
                pytest layer  (imports pytest; thin)
        plugin.py  fixtures.py  hookspecs.py  reporting.py
                              │
                              ▼
                core layer  (no pytest import anywhere)
    GraphQLClient ── Operation builder ── Validation ── Transport
          │                  │                              │
          │            Selection engine                  httpx
          │                  │
          │            Schema (graphql-core GraphQLSchema)
          │                  ▲
          │            SchemaSource (introspection | SDL | custom)
          │
          ├── Response parsing ── Node / NodeList / GraphQLResponse
          ├── Matching ── Matcher / helpers / diff
          ├── Factory ── seeded RNG / ScalarRegistry
          └── Diagnostics ── RequestInfo / redaction / curl
```

### 5.2 Call flow

```
gql.query("user", id="123", fields=AUTO)
   │
   1. resolve operation from schema root Query type
   │      not found -> OperationNotFoundError with near matches
   2. map kwargs to arguments
   │      auto-wrap into single input object if applicable
   │      required missing / unknown name -> ArgumentError
   3. build selection set
   │      AUTO -> SelectionBuilder walks the return type
   │      explicit -> normalize list/dict/Field/Selection/str to AST
   4. assemble the document AST
   │      declare only the variables actually supplied
   5. validate document against schema (graphql-core validate)
   │      invalid -> SelectionError / ArgumentError, no network call
   6. serialize variables through ScalarRegistry
   7. middleware: before_request
   8. transport.send(RequestInfo) -> RawResponse
   │      connect failure -> retry (queries and idempotent mutations only)
   │      timeout -> GraphQLTimeoutError, never retried
   │      non-2xx -> GraphQLHTTPStatusError with the body
   9. parse JSON envelope -> GraphQLResponse
  10. middleware: after_response
  11. record into the active DiagnosticsRecorder
  12. errors present -> GraphQLExecutionError / GraphQLPartialDataError
  13. build Node / NodeList, attach __response__
  14. unwrap the single top-level field and return it
```

### 5.3 Schema layer

`SchemaSource` returns a graphql-core `GraphQLSchema`. Using graphql-core's own schema
object rather than a bespoke type index is a deliberate change from the reference
implementation: it gives parsing, printing, validation and type resolution for free, and
it is the type every GraphQL-aware Python tool already understands.

```python
class SchemaSource(Protocol):
    def load(self) -> GraphQLSchema: ...
    @property
    def fingerprint(self) -> str: ...    # for cache keys and failure reports
```

- `IntrospectionSource(transport)` runs the full standard introspection query from
  graphql-core (`get_introspection_query`) and builds a schema with
  `build_client_schema`. This replaces the reference implementation's hand-written,
  three-level-deep introspection query, which silently truncated deeply wrapped types
  such as `[[Foo!]!]!`.
- `SDLFileSource(path)` reads a `.graphql` file with `build_schema`.
- Users can supply any object satisfying the protocol.

Caching: in memory for the process lifetime. Optional disk cache keyed by
`sha256(url + auth-identity + plugin version)`, off unless `gql_schema_cache_dir` is set,
always bypassed by `--gql-refresh-schema`.

### 5.4 Selection engine

Inputs: a return type, a `SelectionPolicy`, and the schema. Output: a graphql-core
`SelectionSetNode`.

Traversal rules, in order:

1. **Depth.** Stop expanding objects at `max_depth`. `per_type_depth_cap` applies a
   stricter cap for named types.
2. **Cycles.** Detected against the current path only, not a global visited set, so the
   same type may legitimately appear in sibling branches. On a cycle apply
   `cycle_policy`: `stop` omits the branch, `shallow` emits leaf fields plus `id`,
   `id_only` emits `id` alone (or nothing if the type has no `id`).
3. **Required arguments.** A field whose type needs a sub-selection and which has at
   least one non-null argument without a default is **always skipped**. Emitting it
   produces an invalid document. Skipped fields are recorded and surfaced in
   diagnostics.
4. **Relay connections.** When `relay_aware` is on, a type whose name ends in
   `Connection` and which has `edges` and `pageInfo` is expanded as
   `pageInfo { hasNextPage endCursor } edges { cursor node { ... } }`, and the `node`
   expansion does not count `edges` and `node` against the depth budget.
5. **Deprecated fields.** Included unless `include_deprecated=False`.
6. **Interfaces and unions.** Emit `__typename`, the interface's own leaf fields, then
   one inline fragment per possible type.
7. **Excludes.** Patterns from `exclude` (`Type.field`, `*.field`, `Type.*`) are dropped.
8. **Size guard.** Counting fields as they are emitted; exceeding `max_fields` raises
   `SelectionTooLargeError` naming the type, the count and the three concrete remedies
   (lower `max_depth`, add `per_type_depth_cap`, pass `fields=`).
9. **Empty result.** A type that yields no selectable fields raises `SelectionError`
   rather than emitting `{}`, which is invalid GraphQL.

Generated selection sets are memoized per `(type, policy fingerprint)`, so repeated calls
in a session do not re-walk the schema.

### 5.5 Response parsing

Parsing is lazy. `Node` wraps the underlying dict and materializes children on access,
so a large auto-selected response is not copied field by field up front.

The snake_case index for each object is computed once at wrap time (cheap, key count
only), which is where collision detection happens.

### 5.6 Transport

```python
class Transport(Protocol):
    def send(self, request: RequestInfo, *, timeout: float) -> RawResponse: ...
    def close(self) -> None: ...
```

`HttpxTransport` holds one `httpx.Client` for the whole session, with pooling and
configurable verify, proxies and HTTP/2. It is shared by every cloned client; only the
headers differ per clone.

Retry rule: `httpx.ConnectError`, `httpx.ConnectTimeout` and DNS failures are retried
with exponential backoff. `httpx.ReadTimeout`, `httpx.WriteTimeout`, any HTTP status and
any GraphQL error are never retried. Mutations are never retried unless
`idempotent=True`.

### 5.7 Async readiness (not implemented in v1)

Every module except `transport/` and `client.py` is pure and I/O free. Schema handling,
selection building, validation, document assembly, response parsing, matching and the
factory take data in and return data out. Adding `AsyncGraphQLClient` in 2.0 therefore
means adding an `AsyncTransport` protocol and an async client class that reuses the same
core, with no change to the existing public API.

Each worker loads the schema independently. If `gql_schema_cache_dir` is set, workers

the cache the behaviour is N calls, which is documented as the tradeoff for always
testing the live schema.

## 8. Error handling

### 8.1 Hierarchy

```
GraphQLError                        (base; catch this to catch everything)
├── GraphQLClientError               raised before any network call
│   ├── OperationNotFoundError
│   ├── ArgumentError
│   ├── SelectionError
│   ├── SelectionTooLargeError
│   ├── SchemaError
│   └── ScalarNotRegisteredError
├── GraphQLTransportError            network layer
│   ├── GraphQLConnectionError
│   ├── GraphQLTimeoutError
│   └── GraphQLHTTPStatusError
├── GraphQLExecutionError            server returned an errors array
│   └── GraphQLPartialDataError      errors and data both present
├── GraphQLFieldError                response field access
├── WaitTimeoutError                 wait_until exhausted
└── ExpectedErrorNotRaised           expect_error block succeeded
```

Every exception carries the `RequestInfo` when one exists, so the failure report can be
built from the exception alone. This is what makes the diagnostics work identically under
`unittest`, where the pytest report hooks do not run.

### 8.2 Policy

| Situation | Default |
|---|---|
| Unknown operation name | `OperationNotFoundError` before sending, with near matches |
| Unknown or missing argument | `ArgumentError` before sending, with the schema signature |
| Invalid explicit selection | `SelectionError` before sending, with valid field names |
| Document fails schema validation | `SelectionError` with the graphql-core message |
| Connection failure | Retry up to `retries`, then `GraphQLConnectionError` |
| Read timeout | `GraphQLTimeoutError` immediately, never retried |
| HTTP non-2xx | `GraphQLHTTPStatusError` with status and body excerpt |
| Body is not JSON | `GraphQLHTTPStatusError` with the first 500 bytes |
| `errors` present, no `data` | `GraphQLExecutionError` |
| `errors` present, `data` present | `GraphQLPartialDataError` |
| `data` is `null` and no `errors` | `GraphQLExecutionError` (protocol violation) |
| Field not in response | `GraphQLFieldError` on access |
| snake_case collision | `GraphQLFieldError` at wrap time, naming both keys |

### 8.3 Message quality

Every `GraphQLClientError` message must contain: what was wrong, what was expected, and
what to do. Examples the implementation must produce:

```
OperationNotFoundError: no query named 'usr'.
  Did you mean: user, users, userSettings?
  This schema has 84 queries. Run with --gql-show-schema-stats to list them.
```

```
ArgumentError: mutation 'createUser' has no argument 'emial'.
  Signature: createUser(input: CreateUserInput!): User!
  CreateUserInput fields: email, name, role, settings
  Did you mean 'email'?
```

```
GraphQLFieldError: no field 'frist_name' on User.
  Available in this response: id, first_name, last_name, email, status
  Did you mean 'first_name'?
  Note: the field may exist on the type but not be in this selection set.
```

```
SelectionTooLargeError: auto-selection of 'Retailer' produced 3,184 fields (limit 2000).
  Reduce it by one of:
    max_depth=2
    per_type_depth_cap={"User": 1}
    fields=["id", "name"]
```

Suggestions use `difflib.get_close_matches`, which is in the standard library. No fuzzy
matching dependency.

## 11. Testing strategy

### 11.1 The hostile test schema

A single SDL file plus in-process resolvers, designed to break naive implementations. It
must contain:

- Direct self-reference (`User.manager: User`).
- Indirect cycle (`User -> Team -> User`).
- Diamond reuse of the same type in sibling branches (must NOT be treated as a cycle).
- An interface with three implementations.
- A union of unrelated types.
- Relay connections with `edges`, `node`, `pageInfo` and `cursor`.
- Fields with required arguments returning objects (`posts(first: Int!): [Post!]!`).
- Fields with optional arguments and defaults.
- Deprecated fields, including a deprecated object field.
- Custom scalars: `DateTime`, `UUID`, `JSON`, `Upload`, and one unregistered one.
- Deeply wrapped types: `[[String!]!]!`, `[User]`, `[User!]`.
- A type with no `id` field.
- Fields named `id`, `from`, `class`, `type`, `keys`, `items`, `values`, `to_dict`.
- Field pairs that collide in snake_case (`userId` and `user_id`).
- An enum with values that are Python keywords.
- Mutations in three shapes: flat arguments, a single `input` argument, and multiple
  arguments where one is an input object.
- A type with 300 fields, for the size guard.
- Operations returning scalars, lists, nulls and non-null lists of nullables.

### 11.2 Layers

| Layer | Location | Method | Covers |
|---|---|---|---|
| Unit | `tests/unit/` | Pure functions, no I/O | Selection builder, normalizer, validation, naming, matchers, diff, factory, RNG, error messages |
| In-process | `tests/unit/` | `FakeTransport` executing the schema with `graphql_sync` | Full client behaviour, error policy, response parsing, polling, auth cloning |
| Integration | `tests/integration/` | A real HTTP server on a random port | Transport, headers, cookies, timeouts, retries, redirects, non-JSON bodies, non-2xx, connection refused |
| Plugin | `tests/plugin/` | pytest's `pytester` fixture | ini options, CLI flags, fixture wiring and overriding, report sections, header line, hookspecs, xdist |
| Docs | `tests/docs/` | Executed doc examples | Every code block in `docs/` runs against the test schema |
| Contract | optional CI job | Public GraphQL APIs | Real third-party schemas. Allowed to fail, never blocks a release |

### 11.3 Standards

- Coverage gate: 90% line, 85% branch on `src/`.
- Every public error type has a test asserting the exact structure of its message
  (that the fix hint and the suggestion are present). Message quality is a feature, so
  it is tested like one.
- Property-based tests (`hypothesis`, dev dependency only) for the selection builder:
  for any schema shape and any policy, the generated document must always validate
  against the schema and must always terminate.
- Determinism test: the same seed and node id produce byte-identical factory output
  across runs and across Python versions.
- No network access in the default suite. A `pytest-socket`-style guard fails any test
  that opens an unexpected socket.
- The `_core` purity check: a test that fails if `pytest` appears in any import inside
  `src/pytest_graphql/_core/`.

## 14. Unresolved or deferred decisions

### Deferred to a named version

| Item | Target | Note |
|---|---|---|
| File uploads (GraphQL multipart spec) | 1.1 | Contained in the transport and the scalar registry. Additive. `upload` extra reserved. |
| Async client | 2.0 | `AsyncGraphQLClient`, `AsyncTransport`, `agql` fixture. Core is already I/O free. |
| Subscriptions (WebSocket, SSE) | 2.0, after async | Depends entirely on the async layer. |
| In-process ASGI/WSGI transport | 1.1 or 2.0 | Cheap with httpx. Deferred because the primary use case is a running server. |
| Generated `.pyi` stubs from the schema | evaluate at 2.0 | Only if users ask. Adds a build step and stub drift. |
| Query cost or performance assertions | unscheduled | Interesting, unproven. |
| Schema drift reporting between runs | unscheduled | Overlaps with dedicated tools. |

### Rejected

| Item | Reason |
|---|---|
| Record and replay | Makes tests pass against a stale contract, defeating the core goal of testing the live schema. |
| Pydantic response models | Version-conflict risk in test environments, and selections vary per call so fixed models do not fit. |
| Faker as a required dependency | Too heavy for users who never touch the factory. Available as an extra. |
| Keeping the `gql` library | Its `Client`/session model caused the reference implementation's per-call reconnect and duplicate introspection. |
| Server-library-specific integrations | Ties the package to release cycles it does not control. |

### Open, needs a decision before 1.0

1. **Fixture name `gql`.** Short and familiar, but it shadows the `gql()` function from
   the `gql` library for anyone using both. Options: keep `gql`, rename to `graphql`, or
   ship both names. Decide after the first external users report on it.
2. **`__response__` on scalar results.** A scalar or `None` result cannot carry the
   attribute, so `raw=True` is the only route for those. Acceptable, but the asymmetry
   should be reviewed once real usage exists.
3. **Deprecated fields included by default.** Chosen to match the goal of pulling
   everything, but a team with a slow or broken deprecated resolver will hit it. Revisit
   if it causes friction.
4. **Disk cache concurrency.** File locking across xdist workers needs a concrete design
   (`filelock` would be a third dependency, or a stdlib atomic-rename scheme). Decide
   when the disk cache is implemented; it is off by default.
5. **`max_fields` default of 2000.** A guess. Calibrate against real schemas before 1.0.
6. **Relay detection heuristic.** Name-based (`*Connection` plus `edges` plus `pageInfo`)
   is pragmatic but not exact. Consider allowing an explicit list of connection types in
   config if the heuristic misfires.
7. **Interface and union expansion cost.** Emitting an inline fragment for every possible
   type can be very large on schemas with wide unions. May need its own cap separate from
   `max_fields`.
8. **`unittest` diagnostics.** Exceptions carry `RequestInfo`, so messages are good, but
   there is no report section. Consider a `GraphQLTestCase` base class that prints one on
   failure.
